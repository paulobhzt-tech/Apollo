## Inventário do sistema, CPU e RAM

```sh
# Apenas leitura: identidade/relógio/versão, sem enumerar usuários ou credenciais.
date --iso-8601=seconds
cat /etc/os-release
uname -r
uname -m
uptime
lscpu
free -m
swapon --show --bytes
# Se já existir: 6 amostras, aproximadamente 5 segundos, sem stress.
vmstat 1 6
# comm é nome do executável; NÃO substituir por args/command.
ps -eo pid,comm,pcpu,pmem,rss --sort=-rss
```

- [ ] Confirmar vCPU, arquitetura (imagem aprovada ensaiada em x86_64), RAM **real em MiB**, swap, virtualização e load.
- [ ] Registrar CPU ociosa/steal, fila de execução, si/so e MemAvailable em amostras de pico. “Swap existente” não prova pressão; observar troca ativa e histórico de OOM.
- [ ] Consultar gráficos **já existentes** por ao menos um ciclo que contenha o pico real do outro site (preferencialmente 24 h). Uma captura ociosa não comprova folga. Não instalar agente/cron nem rodar benchmark.
- [ ] Inventariar consumo de SO, painel, Apache/PHP, banco/e-mail/antivírus e backup do site. Não parar serviços para abrir espaço.
- [ ] Se permitido ler o journal do kernel, o administrador pode examinar localmente `journalctl -k --since "24 hours ago" --no-pager` e registrar somente ocorrências/horários de OOM/I/O; não copiar o journal integral para o PR.

## Disco, filesystem e containers já existentes

```sh
lsblk -o NAME,TYPE,SIZE,FSTYPE,MOUNTPOINTS
findmnt -o TARGET,SOURCE,FSTYPE,OPTIONS
df -hT
df -i
# Consultar somente arquivos de configuração não secretos do kernel.
cat /sys/kernel/mm/transparent_hugepage/enabled
# Opcional, somente se sysstat já estiver instalado.
iostat -xz 1 3
# Somente se Docker já existir E acesso ao daemon estiver autorizado.
docker version --format '{{.Server.Version}}'
docker info --format '{{json .SecurityOptions}}'
docker ps --format '{{.Names}}\t{{.Image}}\t{{.Ports}}\t{{.Status}}'
docker stats --no-stream --format '{{.Name}}\t{{.CPUPerc}}\t{{.MemUsage}}\t{{.BlockIO}}'
docker network ls
```

- [ ] Registrar bytes/inodes livres no filesystem que conteria `/srv` e no DockerRootDir; não presumir que são partições separadas. Consultar caminho do DockerRootDir apenas por formato específico se necessário, sem dump de configuração.
- [ ] Consultar histórico de latência/utilização de disco já disponível. Não fazer `fio`, `dd`, benchmark Mongo ou `du` recursivo amplo no site ativo.
- [ ] Orçar espaço para **duas imagens** de rollback, dataset/journal/índices, logs limitados, backups temporários e restauração separada. Registrar tamanhos reais após ensaio isolado e manter reserva do host acordada. Volume de dados/backups atual é desconhecido.
- [ ] Confirmar cache/storage adequados ao Mongo 7.0.16. Não alterar THP, filesystem, sysctl ou swap global para acomodar P10 nesta fase.
- [ ] Validar ausência de conflito de sub-rede Docker `172.31.240.0/28`; se necessário e autorizado consultar `docker network inspect --format '{{json .IPAM.Config}}' NOME_DA_REDE` para cada rede existente. Não mostrar containers/env completos.
- [ ] Registrar versão Docker/Compose (`docker compose version` se presente), recursos de cgroup e restrições da hospedagem. Ausência de Docker não autoriza instalá-lo.

## Serviços, portas e firewall

```sh
systemctl list-units --type=service --state=running --no-pager
systemctl list-timers --all --no-pager
# Adicionar só nomes identificados no inventário; não pedir Environment/ExecStart.
systemctl show httpd.service --property=ActiveState,SubState,UnitFileState,MemoryCurrent,TasksCurrent
systemctl show webmin.service --property=ActiveState,SubState,UnitFileState,MemoryCurrent,TasksCurrent
ss -lntup
ip -brief address
ip route show
# Somente se firewalld já existir; consulta, não mudança.
firewall-cmd --state
firewall-cmd --get-active-zones
firewall-cmd --list-all-zones
```

- [ ] Confirmar serviços que usam 80/443 e portas de administração; não confundir porta Webmin 10000 do host com porta 10000 **interna** da Web no container.
- [ ] Confirmar 18082/18443 livres em loopback, ausência de Mongo público e regras IPv4/IPv6. Não sondar bancos existentes nem usar suas credenciais.
- [ ] Registrar regras de ingresso já aplicadas pelo provedor e pelo host; Docker pode ter seu próprio caminho de encaminhamento. Não presumir que firewalld sozinho protege uma porta publicada.
- [ ] Nenhuma mudança em firewall, daemon Docker, SSH ou serviços compartilhados está autorizada.

## SELinux e permissões

```sh
getenforce
sestatus
getsebool httpd_can_network_connect
getsebool httpd_can_network_relay
# Se semanage já estiver instalado, consultar portas, sem -a/-m/-d.
semanage port -l
# Listar contexto apenas de caminhos existentes e aprovados, não seus conteúdos.
ls -Zd /srv /var/lib/docker
```

- [ ] Registrar estado enforcing/policy, contextos de diretórios exclusivos futuros, IDs UID 10001/999/101 e regras necessárias ao proxy. Não alterar donos/labels de diretórios existentes.
- [ ] Administrador pode revisar AVCs localmente com ferramenta já existente; compartilhar só resumo sanitizado. Não gerar política automática com audit2allow.
- [ ] **Proibido nesta fase:** `setenforce`, `setsebool`, `semanage` de escrita, `chcon`, `restorecon`, relabel de árvores do site ou desabilitar SELinux.
- [ ] `httpd_can_network_connect`/outros booleans podem ampliar permissão de **todos** os processos no domínio httpd. A solução deve ser revisada separadamente; preferir host isolado quando exigir mudança global incompatível com o site atual. A referência RHEL não substitui a política local (fonte S4 do diagnóstico).

## Backups existentes — sem produzir nem restaurar agora

- [ ] Identificar no painel, em modo de consulta, agendamento, última execução, status, retenção, destino separado, criptografia e responsável. Não revelar URL assinada/credenciais de destino.
- [ ] Verificar metadata do último backup **já existente** e evidência de restore anterior em outro destino. Se ausente, registrar bloqueio; não clicar em “backup agora” ou restaurar nesta etapa.
- [ ] Confirmar cobertura de arquivos, bancos e configuração do site/Virtualmin/TLS e recuperação de credenciais pelo titular. Um snapshot no mesmo disco não substitui cópia independente.
- [ ] Evidência mínima: data, tamanho/hash já disponível, retenção, último teste de restauração e resultado. Sem evidência, estado **NÃO COMPROVADO**.
